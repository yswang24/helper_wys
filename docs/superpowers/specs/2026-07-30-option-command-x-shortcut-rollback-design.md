# 输入/穿透模式快捷键完全回退设计

## 目标

撤销尚未完成的 `Fn+Tab` 输入/穿透模式快捷键，恢复
`Option+Command+X`（`⌥⌘X`）作为唯一的键盘切换入口。

本次只改变这一组快捷键，不改变录音、截图、回答滚动、浮层显示、
浮层模式切换效果或应用退出方式。

## 最终快捷键

| 快捷键 | 功能 |
| --- | --- |
| `Fn+Control` | 开始/停止录音 |
| `Fn+Shift` | 全屏截图 |
| `Fn+Option` | 开启/关闭回答滚动模式 |
| `Fn+Command` | 显示/隐藏浮层 |
| `Option+Command+X` | 切换输入/穿透模式 |

`Fn+Tab` 不再注册、不再检测，也不再出现在界面说明或错误提示中。
单独按下 `Tab` 以及任何包含 `Fn+Tab` 的操作都由系统和当前应用正常处理，
Helper 不接管 Tab。

## 模式切换

`Option+Command+X` 继续调用现有的
`OverlayController.ensureShownAndToggleMode()`。如果浮层隐藏，先显示浮层，
再在输入模式和穿透模式之间切换。浮层位置、焦点处理、状态广播和视觉效果
全部复用现有逻辑。

如果快捷键被其他程序占用或注册失败，主窗口按现有方式提示
`Option+Command+X` 不可用，Dock 右键菜单仍可作为备用入口。

## 原生快捷键组件

原生组件恢复为只识别以下四组修饰键组合：

- `Fn+Control`
- `Fn+Shift`
- `Fn+Option`
- `Fn+Command`

删除为 `Fn+Tab` 增加的 Carbon 热键注册、Tab 事件、Fn 按下/松开协议和
相关链接配置。组件继续沿用原来的无额外权限方案，不申请辅助功能或输入监控权限。

## 菜单与平台行为

- macOS 顶部菜单栏不创建 Helper 的紫色状态图标。
- macOS Dock 右键菜单继续提供显示/隐藏浮层、切换输入/穿透模式和退出。
- 普通点击 Dock 图标继续恢复主窗口。
- Windows/Linux 继续保留原托盘菜单。

这些菜单行为不因本次快捷键回退而改变。
