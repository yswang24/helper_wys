# Fn 修饰键快捷键设计

## 目标

仅替换 Helper 的全局快捷键，不改变录音、截图、回答滚动、浮层或其他业务功能。

新的 macOS 快捷键映射如下：

| 快捷键 | 功能 |
| --- | --- |
| `Fn+Control` | 开始/停止录音 |
| `Fn+Shift` | 截取鼠标所在显示器的全屏截图并直接解答 |
| `Fn+Option` | 开启/关闭回答滚动模式 |
| `Fn+Command` | 显示/隐藏浮层 |

回答滚动模式开启后，继续沿用现有行为：Helper 全局接管 `↑` / `↓`，方向键触发回答滚动，每次操作重置 30 秒无操作自动关闭计时。

## 范围

- 移除旧的 `CommandOrControl+Alt+H`、`CommandOrControl+Alt+E`、`CommandOrControl+Alt+X`、`CommandOrControl+Alt+S`、`Command+Alt+Up` 和 `Command+Alt+Down` 全局快捷键注册。
- 保留旧快捷键所对应的界面、托盘及 IPC 功能；本次只移除其全局按键入口。
- 不修改录音状态管理、全屏截图流程、滚动距离和超时、浮层显隐逻辑、选区截图功能或穿透/输入模式逻辑。
- 继续仅在 macOS 上提供 Fn 修饰键快捷键。

## 实现设计

### 原生快捷键组件

扩展现有 `Fn+Shift` 原生辅助程序，使其同时识别四种互斥组合：

- Fn 与 Control
- Fn 与 Shift
- Fn 与 Option
- Fn 与 Command

辅助程序继续通过 CoreGraphics 读取全局修饰键状态，不读取字符输入，也不引入辅助功能或输入监控权限。每个组合只在从“未按住”变为“按住”的上升沿触发一次；按住不连发，松开后再次按下可再次触发。目标组合之外若还按住另一目标修饰键，则不触发，避免含糊的多修饰键组合误执行。

辅助程序通过标准输出发送带类型的单行事件，主进程解析完整行并分发到对应回调。拆分数据块、未知行、重复启动、主动停止和异常退出仍按现有容错方式处理。

### 主进程绑定

主进程启动一个原生快捷键辅助进程，并进行以下绑定：

- Control 事件发送现有 `asr:ptt-toggle` IPC。
- Shift 事件调用现有全屏截图触发器。
- Option 事件调用现有回答滚动模式的无方向切换入口。
- Command 事件调用现有浮层显隐控制器。

滚动模式开启时不立即滚动；随后直接按 `↑` / `↓` 才滚动。关闭时释放两个方向键注册。方向键注册失败、30 秒无操作关闭和程序退出清理均保持现有行为。

### 错误反馈

原生辅助程序缺失、不可执行、启动失败或异常退出时，仍通过主窗口现有的“快捷键不可用”提示统一反馈。因为四个组合共享一个辅助程序，组件不可用时提示四组 Fn 快捷键均不可用。

## 测试与验证

- 原生自测覆盖四个合法组合、额外修饰键阻止触发、按住不连发、松开后可重触发和启动时已按住不误触发。
- TypeScript 单元测试覆盖四种事件的完整行与拆分行解析、未知事件忽略、生命周期和错误反馈。
- 回答滚动模式测试覆盖无方向切换：开启不立即滚动，`↑` / `↓` 正常滚动，第二次切换关闭，30 秒超时保持不变。
- 运行原生 Universal 构建及自测、项目单元测试、类型检查和构建。
- README 中所有快捷键及相关用法说明同步为新组合键，但不改变功能说明。
